# VCS Workflow

Git is the repository's version-control backend. The authoritative operational
rules remain [Project Workflow](./workflow.md) and
[Continuous Autonomous Execution](./autonomy.md).

- Preserve unrelated changes and use an isolated `codex/` worktree for overlapping work.
- Use Conventional Commits and stage only named task-owned paths.
- Run the required repository harness before opening a pull request.
- Record task evidence in the track; Git notes are not required.
- Keep local validation, hosted checks, merge, capture and publication distinct.
- Do not retire a donor, rewrite history or delete archive data as housekeeping.

This handshake records existing project policy; it grants no new authority.
