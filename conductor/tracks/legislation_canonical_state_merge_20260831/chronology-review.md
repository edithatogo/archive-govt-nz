# Chronology review correction

Review of PR #297 at c489c5de9d0485f5c0137f541ecd5e079323d08e found that
lexical comparison could choose an earlier checkpoint instant when accepted
timestamps use different UTC offsets. For example, 2026-09-01T00:30:00+10:00
sorts after 2026-08-31T23:00:00Z but represents an earlier instant.

A focused regression run observed one failure and two passes before correction.
The merger now compares parsed timezone-aware instants and uses the original
timestamp string only as a deterministic tie-breaker for equivalent instants.
This preserves original spelling and the existing selection for same-format
timestamps. Regression cases cover mixed offsets, equivalent instants, ordinary
UTC timestamps, reversed parent order and idempotent merged-state reuse.

All 53 merger tests pass after correction. Focused Ruff format/lint, strict
typing and repository Conductor validation (74 tracks) pass. No full native or
mutation rerun is claimed for this correction; fresh hosted checks are required.

The prior executed package and its bound receipts remain unchanged and attributed
to their original software revision. No packet was regenerated by this review;
the existing real package's byte equality under revised software is not claimed.
The original no-overwrite, source-rights and no-publication boundaries remain.
